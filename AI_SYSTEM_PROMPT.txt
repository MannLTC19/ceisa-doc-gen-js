RINGKASAN APLIKASI
================================================================================

Aplikasi ini adalah "Document Generator" yang membantu tim Bea Cukai Indonesia 
(khususnya IKC PSI) dalam membuat dokumentasi proyek secara terstruktur dan otomatis.

TUJUAN UTAMA:
- Mempermudah pembuatan dokumentasi teknis proyek
- Mengintegrasikan OCR untuk membaca dokumen scan/PDF secara otomatis
- Mengorganisir informasi proyek dalam format standar internasional
- Mengekspor hasil dokumentasi ke berbagai format (Excel, PDF, DOCX)
- Menerapkan standar Bea Cukai dengan visual branding yang konsisten

TARGET PENGGUNA:
- Project Manager di Bea Cukai
- Business Analyst
- System Architect
- Technical Writer
- Stakeholder sektor pemerintah Indonesia

2. UTILITY MODULES (Non-UI Logic)
──────────────────────────────────

src/utils/ocrProcessor.js
├─ Fungsi: Core OCR engine menggunakan Tesseract.js
├─ Exports:
│   ├─ initializeOCRWorker(): void
│   │   └─ Lazy load Tesseract OCR worker (sekali saja)
│   ├─ extractTextFromImage(imageFile): Promise<{text, confidence}>
│   │   └─ Read image dengan OCR
│   ├─ extractTextFromPDF(pdfFile): Promise<{text, pages}>
│   │   └─ Render setiap page PDF ke canvas → OCR pada setiap page
│   ├─ cleanOCRText(dirtyText): string
│   │   └─ Post-process untuk improve quality
│   └─ terminateOCRWorker(): void
│       └─ Cleanup memory
├─ Dependencies:
│   └─ tesseract.js (npm package)
├─ Performance:
│   └─ Worker thread, non-blocking
└─ Supported Languages: Indonesian (ind), English (eng)


src/utils/ocrIntegration.js
├─ Fungsi: Smart wrapper dengan quality detection & fallback logic
├─ Exports:
│   ├─ extractDocumentWithOCR(file, options): Promise<{text, quality, method, confidence}>
│   │   └─ Main function dengan intelligent fallback
│   ├─ assessTextQuality(text): number (0-100)
│   │   └─ Score berdasarkan: whitespace density, alphanumeric ratio, corruption
│   ├─ batchExtractWithOCR(files, onProgress): Promise<array>
│   │   └─ Process multiple files dengan progress callback
│   └─ getRecommendedOCRConfig(file): object
│       └─ Auto-detect optimal settings berdasarkan file characteristics
├─ Quality Scoring Algorithm:
│   └─ Evaluasi: 
│       ├─ Whitespace density (30%)
│       ├─ Alphanumeric ratio (40%)
│       ├─ Character corruption detection (20%)
│       └─ Length validation (10%)
├─ Fallback Strategy:
│   └─ Try Native → If quality < 50 → Use OCR → If OCR fails → Return raw
└─ Use Case:
    └─ Detect kalau native PDF extraction jelek → auto trigger OCR


src/utils/fileHelpers.js
├─ Fungsi: Unified document extraction handler
├─ Exports:
│   ├─ extractDocumentPages(file): Promise<array>
│   │   └─ Auto-detect file type & delegate ke extractor yang tepat

│   │   └─ Delegate ke ocrProcessor untuk gambar
│   └─ detectFileType(file): string
│       └─ MIME type detection
├─ Supported Formats:
│   ├─ PDF (.pdf)
│   ├─ Word (.docx)
│   ├─ Excel (.xlsx)
│   ├─ Images (.png, .jpg, .jpeg, .gif, .webp)
│   ├─ Plain text (.txt)
│   └─ Dapat di-extend untuk format lain
└─ Dependencies:
    ├─ pdfjs-dist (PDF parsing)

================================================================================
ALUR KERJA & DATA FLOW
================================================================================

SCENARIO 1: User membuat project documentation baru
──────────────────────────────────────────────────

1. User buka aplikasi di http://localhost:5173
2. App.jsx render dengan ConfigProvider theme
3. Default state: Tab 1 (TabKajian) aktif
4. User mengisi form fields secara manual atau upload dokumen

   Input Manual Flow:
   ├─ User type di TextArea "Latar Belakang"
   ├─ onChange event → handleUpdateField()
   └─ projectData state updated di App.jsx

   Upload Document Flow:
   ├─ User drag-drop PDF ke FileUploadWithOCR
   ├─ Component detect file type = PDF
   ├─ Try native PDF extraction (pdfjs-dist)
   ├─ Assess text quality
   ├─ If quality < 50: Trigger OCR (Tesseract.js)
   ├─ OCR process each page
   ├─ Clean text (remove artifacts)
   ├─ Quality score = 78 (example)
   ├─ Callback onTextExtracted(text) triggered
   └─ Text auto-fill ke "Latar Belakang" field

5. User pindah tab ke TabBRD
   ├─ Form state tetap di App.jsx (tidak hilang)
   ├─ User isi "Proses Bisnis", tambah modules/features
   └─ Each Add/Remove button trigger handleAddArray(), handleRemoveArray()

6. Repeat untuk TabFSD, TabCharter, TabPenelitian
   └─ Semua data terakumulasi di projectData object

7. User klik "Export to Excel" button
   ├─ Data validation di excelGenerator.js
   ├─ Generate multi-sheet workbook
   ├─ Apply styling (colors, borders, fonts)
   └─ Trigger browser download (project-doc.xlsx)

8. User klik "Print" button
   ├─ CSS @media print aktif (hide UI buttons)
   ├─ Print-friendly layout render
   └─ User print/save as PDF


SCENARIO 2: Data validation & quality checks
───────────────────────────────────────────

1. During OCR processing:
   ├─ Tesseract extract text → "hasil scan: 8283 kata..."
   ├─ assessTextQuality(text) calculate score:
   │   ├─ Check whitespace density
   │   ├─ Check alphanumeric ratio
   │   ├─ Check for common OCR artifacts (###, |||, etc.)
   │   └─ Return score 0-100
   ├─ If score 80-100: "Excellent - native extraction"
   ├─ If score 50-79: "Good - OCR processed"
   ├─ If score < 50: "Low quality - manual review recommended"
   └─ Display to user with star rating

2. Before export:
   ├─ validateRequiredFields(projectData)
   ├─ Check: nama proyek, background, goals, scope required
   ├─ If missing: Show warning toast "Please fill in required fields"
   └─ If valid: Proceed dengan export


SCENARIO 3: Tab switching & state persistence
──────────────────────────────────────────────

1. User fill form in TabKajian
   └─ Data stored in projectData state (App.jsx)

2. User click TabBRD tab
   ├─ selectedTab state change to 'brd'
   ├─ TabKajian unmount (state NOT lost - di App)
   ├─ TabBRD mount
   └─ User see empty TabBRD form OR pre-filled data if already entered

3. User click back to TabKajian
   ├─ selectedTab state change back to 'kaj'
   ├─ TabBRD unmount (state NOT lost)
   ├─ TabKajian mount
   └─ User see previously entered data (restored from projectData)

State Management Philosophy:
├─ ALL state di App.jsx (single source of truth)
├─ Tabs adalah "dumb" components (receive props, call callbacks)
├─ No component-level state (getState(), setState())
├─ All changes go through App.jsx handlers
└─ No data loss on tab switches

FITUR-FITUR UTAMA

1. OCR (Optical Character Recognition) System
─────────────────────────────────────────────
Teknologi: Tesseract.js v7.0.0
Fitur:
├─ Support multi-language: Indonesian + English
├─ Process PDFs dengan render-to-canvas approach
├─ Process scanned images (.png, .jpg, .jpeg, .gif, .webp)
├─ Auto-detect quality dan provide confidence score
├─ Intelligent fallback: Try native → If bad → Use OCR
├─ Batch processing dengan progress tracking
├─ Non-blocking (worker thread)
├─ Cleanup setelah selesai (memory management)
├─ Error handling dengan user-friendly messages
└─ Extract text → Auto-fill form fields

Quality Scoring:
├─ Whitespace density analysis (30% weight)
│   ├─ Too many blank lines = scan error
│   ├─ Proper spacing = good extraction
│   └─ Dense text = potentially corrupted
├─ Alphanumeric ratio (40% weight)
│   ├─ Indonesian documents expect 60-80% alphanumeric
│   ├─ Too high special chars = OCR artifact
│   └─ Too low = incomplete extraction
├─ Corruption detection (20% weight)
│   ├─ Look for common OCR artifacts: ###, |||, ****
│   ├─ Character sequences that don't make sense
│   └─ Unknown unicode blocks
└─ Length validation (10% weight)
    ├─ If extracted text < 50 chars = likely failed
    └─ If extracted text > 50k chars = likely corrupted

Use Cases:
├─ Import scanned project requirements document
├─ Extract text dari photo of whiteboard/sketch
├─ Read Indonesian government forms/templates
├─ Automate data entry from hardcopy documents
└─ Support auditors yang punya old paper documents

================================================================================
TROUBLESHOOTING GUIDE
================================================================================

Problem: OCR tidak extract text
Solusi:
├─ Check file format adalah PDF/image yang valid
├─ Verify Tesseract.js worker loaded
├─ Check browser console untuk error messages
├─ Try manual text entry sebagai fallback

Problem: Export Excel gagal
Solusi:
├─ Verify data di semua fields valid
├─ Check localStorage tidak full
├─ Try export dengan minimal data dahulu
├─ Check browser dev console

Problem: Tab data hilang
Solusi:
├─ Check localStorage enabled
├─ Verify projectData state tidak di-reset
├─ Check tab switching event handler
├─ Use browser dev tools Redux extension

Problem: Styling tidak apply
Solusi:
├─ Verify antd-custom.css imported di main.jsx
├─ Check CSS load order (reset → theme → custom)
├─ Clear browser cache (Ctrl+Shift+Del)
├─ Verify ConfigProvider wrapping App.jsx

Problem: Performa lambat dengan OCR
Solusi:
├─ Reduce OCR language count (default: ind+eng)
├─ Process smaller PDFs dahulu
├─ Check system resources (RAM, CPU)
├─ Use batch processing dengan progress tracking

DEVELOPER GUIDELINES
================================================================================

Code Style:
├─ Use camelCase untuk variables/functions
├─ Use PascalCase untuk React components
├─ Use UPPER_SNAKE_CASE untuk constants
├─ Keep functions small & focused
├─ Add JSDoc comments untuk exported functions
└─ Follow ESLint rules

Component Structure:
├─ Functional components (no class components)
├─ Use React hooks (useState, useEffect, etc.)
├─ Props di-destructure
├─ One component per file
├─ Export as default
└─ Keep JSX readable

State Management:
├─ Centralized dalam App.jsx
├─ Pass callbacks untuk child component updates
├─ No deep prop drilling (use context if needed)
├─ Immutable state updates
└─ Never mutate state directly

Performance:
├─ Use React.memo untuk heavy children
├─ Lazy load components (dynamic import)
├─ Optimize image sizes
├─ Cache expensive calculations
├─ Minimize re-renders
└─ Code split pada route/tab

Naming Conventions:
├─ handleXxx() untuk event handlers
├─ useXxx() untuk custom hooks
├─ isXxx() / hasXxx() untuk booleans
├─ selectXxx() untuk selector functions
├─ fetchXxx() / getXxx() untuk API calls
├─ validateXxx() untuk validation functions
└─ formatXxx() untuk formatting functions
